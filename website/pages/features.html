Features

One program. Every node is the same.

The open-source core connects machines anywhere. The enterprise edition adds who may use which machine, when, and with which rights. Both are the same meshvpn binary.

The network

No coordination server, no account, no cloud. The machines are the network.

Gossip, not a control plane

Each node signs its own record (name, addresses, neighbors) and gossips it. The state is saved on disk, so the network survives losing any node, including the first one.

Direct paths through NAT

Nodes probe each other over UDP and punch through both NATs. IPv6 addresses are candidates too, which gets through mobile networks where IPv4 can't. LAN paths win when both sides share one.

Relays when nothing else works

Nodes that can't reach each other are connected through the shortest path over other nodes. Relays forward packets they can't read or forge.

SSH-only networks

A machine that may only open an SSH connection joins with --ssh user@jump. meshvpn runs and supervises the reverse tunnel and a SOCKS proxy over it.

Stable addresses and names

Every node gets an address in 100.64.0.0/10 derived from its key, and a <name>.mesh name. Rename a node and its address, permissions and links stay.

Invites and admins

Admins issue invites that admit one node within 24 hours by default. Banning a node rotates the network key and sends the new key, sealed, to everyone else.

Exit nodes

Send a machine's internet traffic through another node, to appear with the office address or give an offline machine a way out. Nothing leaks while the exit is down.

Containers without privileges

Without /dev/net/tun, meshvpn switches to userspace mode by itself: services in the container are reachable, programs reach out through a SOCKS proxy.

No root needed

A rootless install lives in your home directory and runs as a user service. Machines without internet get installed from a jump host with deploy.sh.

open source

Getting onto machines

Password-less SSH, decided per machine

sudo meshvpn ssh opens a grid: which user of which node may log in as whom. Keys are bound to the node's mesh address, which can't be spoofed.

A built-in SSH server

Docker images rarely have sshd. meshvpn answers SSH itself with the same rules: shells, commands, scp and sftp, port forwarding. No host-key prompts on the mesh.

The desktop in your browser

meshvpn desktop gpu-box opens a remote desktop, even in a container without an X server. Clipboard, files, uploads by drag and drop, and Xfce if you want it.

A console for SSH-only access

Run meshvpn in a terminal for a full-screen view of all nodes, with tabs for shells on each, like tmux for the whole network.

Doctor

sudo meshvpn doctor checks the daemon, firewalls, peers, UDP paths, NAT type, SSH logins, admins and updates, and says how to fix each problem.

Updates you control

Nodes tell you about new releases but never install them by themselves. meshvpn update verifies the SHA-256 checksums before installing.

Working across many nodes

Built for people and for AI agents that drive many machines at once.

CommandWhat it does
meshvpn nodes --free-gpus 4Nodes with their CPU, memory, disk and GPUs (memory, use, driver, CUDA), published by the nodes themselves.
meshvpn exec tag:gpu -- nvidia-smiRun a command on many nodes in parallel, with output and exit code per node.
meshvpn cp ./code tag:gpu:/srv/Copy to or from many nodes at once.
meshvpn net matrix --measureRound-trip times, throughput and direct LAN paths between all nodes.
meshvpn gpu reserve tag:gpu -n 2Reserve GPUs so no other job or agent takes them. Prints CUDA_VISIBLE_DEVICES.
meshvpn launch --gpus 4 tag:gpu -- torchrun train.pyStart a distributed job: every node gets MASTER_ADDR, NODE_RANK and NCCL settings; if one node fails, all stop.
sudo meshvpn share ./dataset · fetch <id>Share a dataset and download it from all nodes that have it at once, verified in 4 MB chunks.
meshvpn guide · meshvpn mcpInstructions for AI agents, and an MCP server with tools for nodes, jobs, GPUs and data.

Every command takes --json, and exit codes are stable. Nodes are selected with all, tag:<tag>, names or addresses.

enterprise

Shared hardware, controlled

For benches, labs and clusters that many people and agents use. Unlock with a license; try it for 30 days.

Bookings

One booking covers several devices. Exclusive bookings never overlap, shared ones run alongside other shared ones. Or book --count 4 free devices of a tag, now or later.

Personal accounts with sudo

During a booking the device has an account for the user, with sudo if the rule allows. At the end the account is locked, sudo removed and the user's processes stopped.

A gateway for outside users

Users don't install anything: ssh -J jump@gw alice@dev1.mesh. The gateway lets each key through to its booked devices, and nowhere else.

A central, signed policy

Users and their SSH keys, groups, which devices can be booked by whom and for how long, gateways. Admins sign it, every node enforces it itself.

AI agents as users

Agents have the same rights as people and book through the CLI or the portal's API with an API key. Their bookings show up like everyone else's.

The portal

One web interface and REST API for all networks. Password plus two-factor login; users book, manage their SSH keys and API keys; admins manage everything.

Audit log

meshvpn audit shows who changed what, who booked which device, and who accepted the license terms, with time.

Licenses that travel with the policy

Install a license once; it reaches every node. When it expires, the last policy stays in force, so benches stay protected.

Self-hosted

Everything runs on your machines. Only a trial request goes to PlugOvr's license server, and updates come from GitHub. Your traffic and your policy never leave your network.
