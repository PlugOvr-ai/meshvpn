Set up the portal

The portal is one web interface and REST API for all your networks. Admins manage users, groups, devices, gateways and licenses there. People book devices and manage their keys. Agents use the same API with an API key.

You need: a Linux server with systemd (x86_64 or ARM64), a host nameTime: 20 minutes

Steps

1. Install 2. HTTPS 3. First login 4. Add a network 5. Invite nodes 6. License 7. Users and groups 8. Devices and gateways 9. Day to day

STEP 1

Install

The installer puts the enterprise meshvpn and meshvpn-portal into /usr/local/bin, creates the first admin and starts the systemd service meshvpn-portal:

on the portal server
$ curl -fsSL https://github.com/PlugOvr-ai/meshvpn-enterprise-releases/releases/latest/download/install-portal.sh \
    | sudo sh -s -- --public-host portal.example.com --admin ops
OptionWhat it does
--public-hostRequired. The name or address nodes reach this server at.
--admin opsCreates the first admin; asks for the password.
--tls-cert, --tls-keyServe HTTPS directly, on 0.0.0.0:443 unless --listen says otherwise.
--listenAddress and port. Default: 127.0.0.1:8080 without a certificate.

Without --admin, create the first admin afterwards with sudo meshvpn-portal add-admin ops. The portal keeps its data in /var/lib/meshvpn-portal, readable by root only. Logs: journalctl -u meshvpn-portal -f.

Port taken? If another program already uses port 8080 (a Docker container, for example), the service stops with "Address in use". Pick a free port with --listen 127.0.0.1:8081, or change it in /etc/systemd/system/meshvpn-portal.service and run sudo systemctl daemon-reload && sudo systemctl restart meshvpn-portal.

STEP 2

HTTPS

Without a certificate the portal serves plain HTTP on localhost. Put a reverse proxy with HTTPS in front. With Caddy, which gets the certificate by itself, this is the whole configuration:

/etc/caddy/Caddyfile
portal.example.com {
    reverse_proxy 127.0.0.1:8080
}

Or pass your own certificate to the installer: --tls-cert /etc/meshvpn-portal/cert.pem --tls-key /etc/meshvpn-portal/key.pem.

STEP 3

First login

Open https://portal.example.com and log in as ops. The first login sets up the second factor: scan the QR code with any authenticator app and enter the code. From then on every login needs password and code.

If someone loses their phone, an admin resets it on the server; at the next login they set it up again:

$ sudo meshvpn-portal reset2fa alice

STEP 4

Add a network

Under Networks → Add a network, either:

  • create a new one: the portal starts the network and is its admin, or
  • join an existing one with an invite from one of its admins (sudo meshvpn invite). Then an admin of that network makes the portal an admin too:
on an admin node of the network
$ sudo meshvpn admin add portal

Also enter the gateway address: where users connect from outside, e.g. gw.example.com. The portal shows it to users in their login commands.

For each network the portal runs its own meshvpn instance, on ports 7900 and up (TCP and UDP). Open them in the server's firewall:

$ sudo ufw allow 7900:7999/tcp
$ sudo ufw allow 7900:7999/udp

STEP 5

Invite nodes

Invite a node in the network's card prints an install command with an invite. Run it on the device or gateway:

on a new node
$ curl -fsSL https://github.com/PlugOvr-ai/meshvpn-enterprise-releases/releases/latest/download/install.sh | sudo sh -s -- join mesh1-...

Tag the node so rules can find it, e.g. sudo meshvpn tag add bench or sudo meshvpn tag add gateway.

STEP 6

License

Each network needs a license. In the network's card, tick I accept the license terms, then:

  • enter your e-mail and company and click Start a 30-day trial, or
  • paste the license file you got from us and click Install license.

The card shows the license holder and the end date. Plans are on the pricing page; the terms are at licenses.plugovr.ai/terms.

STEP 7

Users and groups

Under Users, add people and agents. They're the same in all networks of the portal.

  • People get a password and set up their second factor at the first login. Paste their SSH public keys, or let them add the keys themselves under Account.
  • Agents: tick agent and leave the password empty. They log in with API keys only; see An AI cluster with agents.
  • Admins: tick admin.

Groups (e.g. testers with alice and bob) make rules shorter.

STEP 8

Devices and gateways

In each network's card:

  • Bookable devices: a node name or tag:bench, who may book (group:testers, alice; empty means everyone), the longest booking (8h) and whether users get sudo.
  • Gateways: tag:gateway or a node name. Without a gateway, users can't reach devices.

STEP 9

Day to day

  • People see the devices, book one or several for a time, exclusive or shared, and cancel their bookings under Devices and My bookings. The portal shows them the ssh -J command for each booked device.
  • Everyone manages their SSH keys and API keys under Account.
  • Admins open each network's Audit log: who changed and booked what.
  • Updates: run the installer again. It keeps the data in /var/lib/meshvpn-portal. Update the nodes with sudo meshvpn update.
