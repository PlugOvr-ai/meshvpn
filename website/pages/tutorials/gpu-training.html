Distributed training across nodes

GPU servers in the lab, a cloud machine, a workstation under a desk. meshvpn connects them, works out the rendezvous for PyTorch, starts the job on every node and stops all of them if one fails.

You need: two or more Linux nodes with Python and PyTorchExample: examples/distributed-training (GPU or CPU)

Steps

1. Prepare the nodes2. Look at the group3. Run on many nodes 4. Share the data5. Train6. Reserve GPUs 7. Long runs8. Let an agent do it

STEP 1

Prepare the nodes

Each training node needs:

  • meshvpn as root, with its network interface mesh0. NCCL and gloo open their own connections and need a real interface. In containers, start them with --cap-add=NET_ADMIN --device /dev/net/tun.
  • A tag, so the group is easy to select.
  • SSH logins without a password from the machine you launch on, as the same user on every node.
  • The same Python and PyTorch versions everywhere. A virtualenv or conda environment is fine.
on each GPU node
$ sudo meshvpn tag add gpu
$ sudo meshvpn ssh allow alice@laptop --as alice   # or join with --ssh-allow-all alice

The machine you launch from can be any node, also one without GPUs.

STEP 2

Look at the group

Nodes publish their hardware themselves, so this needs no login:

$ meshvpn nodes tag:gpu                  # online? CPUs, memory, disk, GPUs, driver, CUDA
$ meshvpn nodes --free-gpus 4            # nodes with at least 4 free GPUs
$ meshvpn gpu list tag:gpu               # free, busy or reserved
$ meshvpn net matrix --measure tag:gpu   # latency, throughput, shared LANs
FROM  TO          RTT          MESH  LAN PATH           AGE
gpu1  gpu2     0.0 ms    860 Mbit/s  172.23.0.4         0s
gpu2  gpu1     1.0 ms    863 Mbit/s  172.23.0.3         0s

A LAN PATH for every pair means the job will run over the LAN at full speed. If any pair lacks one, everyone uses the mesh: NCCL hangs when some nodes use one network and some another. Measure once before the first job of a new group.

STEP 3

Run commands and copy files on many nodes

Selectors address nodes: all, tag:gpu, node names or mesh IPs. Commands run in parallel and report per node.

$ meshvpn exec tag:gpu -- hostname                      # test the logins
$ meshvpn exec tag:gpu -- nvidia-smi
$ git clone https://github.com/PlugOvr-ai/meshvpn && cd meshvpn/examples
$ meshvpn cp ./distributed-training tag:gpu:/home/$USER/
$ meshvpn cp tag:gpu:/srv/out.log ./logs                # downloads go to logs/<node>/
torchrun not found? A command started over SSH doesn't activate conda or a virtualenv. The example's run.sh activates the environment and passes meshvpn's rendezvous to torchrun. Adjust its activation line, or call torchrun by its full path.

STEP 4

Share the data

Copy small datasets like code. Share big ones once and let the nodes fetch them in parallel. Every node that has a piece serves it to the others, over the LAN where possible. Each 4 MB chunk is verified, and interrupted downloads resume.

where the data is
$ cd distributed-training && python prepare_data.py
$ sudo meshvpn share data --name spirals   # prints an id
on each training node
$ sudo meshvpn fetch <id> ~/distributed-training
gpu1 fetched spirals into /home/agent/meshvpn-example: 962 kB in 0.1s (126 Mbit/s) from hub 962 kB
gpu2 fetched spirals into /home/agent/meshvpn-example: 962 kB in 0.1s (109 Mbit/s) from gpu1 962 kB

gpu2 got the data from gpu1, which had just fetched it. meshvpn objects lists what is shared and where.

STEP 5

Train

$ meshvpn launch tag:gpu --workdir distributed-training -- ./run.sh --epochs 3
job bb8ae227: ./run.sh --epochs 3 on 2 node(s), master gpu1 via lan
[gpu1] backend gloo, rendezvous 172.23.0.3:29500, network lan (eth0)
[gpu1] epoch 1/3: loss 0.9680, test accuracy 66.4%, 17,104 samples/s
[gpu1] epoch 2/3: loss 0.6676, test accuracy 77.8%, 14,897 samples/s
[gpu1] epoch 3/3: loss 0.4983, test accuracy 81.6%, 17,304 samples/s
job bb8ae227: succeeded

launch picks rank 0 (the first node by name, or --master gpu3), sets MASTER_ADDR, MASTER_PORT, NNODES, NODE_RANK and NCCL_SOCKET_IFNAME on every node, and adds the rendezvous arguments when the command is torchrun. Each node's output is prefixed with its name. If one node fails, the others are stopped. Closing the terminal stops the job on all nodes.

Another launcher (DeepSpeed, Lightning, Accelerate, JAX)? Use meshvpn only for the rendezvous, on each node:

$ eval $(meshvpn net env --master gpu1 tag:gpu)
$ echo $MASTER_ADDR $NODE_RANK $NNODES $NCCL_SOCKET_IFNAME

STEP 6

Reserve GPUs

On shared machines, reserve GPUs so two jobs don't land on the same ones. The node with the GPUs grants the reservation, so reservations never collide.

$ meshvpn launch tag:gpu --gpus 4 --workdir distributed-training -- ./run.sh
$ meshvpn gpu reserve gpu1 -n 2 --for 4h --note "debugging"   # prints CUDA_VISIBLE_DEVICES
$ meshvpn gpu release <id>

--gpus 4 reserves 4 free GPUs on every node before anything starts, or fails right away. It sets CUDA_VISIBLE_DEVICES, starts one process per GPU, and releases the reservation at the end. Reservations of a crashed launcher expire after 15 minutes. They are advisory, like Slurm without cgroups.

STEP 7

Long runs

$ meshvpn launch tag:gpu --detach --workdir distributed-training -- ./run.sh --epochs 500
$ meshvpn jobs list           # running, succeeded, failed, stopped
$ meshvpn jobs show <id>      # state, environment, the end of each node's log
$ meshvpn jobs logs <id> --node gpu1
$ meshvpn jobs stop <id>

A detached job is supervised from the machine you launched on, so launch from a node that stays up. Get results back with meshvpn cp gpu1:/home/$USER/distributed-training/checkpoints ./results/.

STEP 8

Let an AI agent do it

Every command takes --json, errors included, and exit codes are stable: 0 ok, 1 error, 2 usage, 3 meshvpn not running, 4 needs root, 5 not found.

meshvpn guide prints instructions for agents: the rules, the commands for each task, and the network right now. Point your agent at it, for example in AGENTS.md: "Run meshvpn guide before working with other machines."

Claude Code
$ claude mcp add meshvpn -- meshvpn mcp   # MCP server: list nodes, reserve GPUs, launch, read logs
$ mkdir -p ~/.claude/skills/meshvpn && meshvpn guide --skill > ~/.claude/skills/meshvpn/SKILL.md

Any MCP client works. The tools include list_nodes, exec, copy_to_nodes, gpu_reserve, launch, job_status, share, fetch and doctor.

Shared cluster with bookings? With meshvpn enterprise, agents book GPU nodes like people and get access only for the booked time. See AI cluster with agents.
