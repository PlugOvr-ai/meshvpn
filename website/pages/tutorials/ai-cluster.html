Tutorial · enterprise · 25 min

An AI cluster with bookings for people and agents

Your GPU servers become a pool that people and AI agents book: "4 free A100 nodes for 3 hours". Agents book through the portal's API with a key and have the same rights as a person. When the booking ends, their access ends too.

You need: GPU servers on Linux, a gateway, the portalBuilds on: Book a test bench

Steps

1. The setup 2. Tag the GPU nodes 3. Agents as users 4. A rule for the pool 5. An API key 6. Book through the API 7. Log in and train 8. Cancel and clean up 9. Teach your agent

STEP 1

The setup

This tutorial assumes a network with the enterprise build on every node, a gateway, and a license or trial, as in Book a test bench. Here the devices are GPU servers gpu1 to gpu8. The portal runs as admin of the network (Set up the portal); it gives agents an HTTP API.

Bookings make sure two jobs don't land on the same machines. A booking is all or nothing: either all requested nodes are free for the whole time, or nothing is booked.

STEP 2

Tag the GPU nodes

on gpu1 ... gpu8
$ sudo meshvpn tag add a100

Or tag them when they join: sudo meshvpn join mesh1-... --tag a100. Every node publishes its hardware, so you can check what's in the pool from any node:

$ meshvpn nodes tag:a100
$ meshvpn device list

STEP 3

Agents as users

An agent is a user with the agent flag and its own SSH key. Create the key pair where the agent runs:

where the agent runs
$ ssh-keygen -t ed25519 -N "" -f ~/.ssh/agent7 -C agent7

Then add the agent with its public key. In the portal: Users, tick agent, paste the key, leave the password empty (agents use API keys only). On an admin node it's the same as for people:

on an admin node
$ sudo meshvpn user add agent7 --key-file agent7.pub --agent
$ sudo meshvpn group set ml alice agent7
Portal or CLI. When the portal manages a network, add users and groups in the portal. It keeps them the same in all its networks.

STEP 4

A rule for the pool

on an admin node
$ sudo meshvpn device add tag:a100 --who group:ml --max 12h

In the portal, the same is under Networks → Bookable devices: tag:a100, who group:ml, longest 12h, sudo on or off.

STEP 5

An API key

People create their own keys in the portal under Account → API keys. A key for an agent account comes from an admin, through the API: log in once (with your 2FA code), then create the key for agent7. The key is shown once.

as a portal admin
$ curl -s -c cookies -H "Content-Type: application/json" \
    -d '{"user": "ops", "password": "...", "code": "123456"}' https://portal.example.com/api/login
$ curl -s -b cookies -H "Content-Type: application/json" \
    -d '{"label": "training agent", "user": "agent7"}' https://portal.example.com/api/apikeys
{"id": "k1a2b3c4d", "key": "mvk_...", "user": "agent7", "note": "shown only now - store it safely"}

The agent sends it on every request as Authorization: Bearer mvk_.... Revoke a key with DELETE /api/apikeys/<id> or in the portal.

STEP 6

Book through the API

First the agent looks at the networks, their devices and the current bookings:

$ export MV="Authorization: Bearer mvk_..."
$ curl -s -H "$MV" https://portal.example.com/api/networks

Then it books 4 free nodes from the pool for 3 hours:

$ curl -s -H "$MV" -H "Content-Type: application/json" \
    -d '{"network": "lab", "selector": "tag:a100", "count": 4, "duration": "3h", "note": "sweep lr=3e-4"}' \
    https://portal.example.com/api/book
{"ok": true, "message": "booked gpu2, gpu3, gpu5, gpu6 for agent7 exclusively from ... (id b7c1e2f0)", ...}
FieldMeaning
networkthe network's name in the portal
devicesnode names, e.g. ["gpu1", "gpu2"]; or instead:
selector + countpick this many free nodes, e.g. "tag:a100" and 4
from"now" (default), "+1h", or "2026-11-03T09:00+01:00"
duration or until"3h", or an end time
exclusivetrue by default; false for a shared booking
notefree text, shown in the bookings
useradmins only: book for someone else

STEP 7

Log in and train

The portal tells the agent how to reach a booked node:

$ curl -s -H "$MV" https://portal.example.com/api/networks/lab/connect/gpu2
{"command": "ssh -J jump@gw.example.com agent7@gpu2.mesh", "ssh_config": "Host *.mesh\n    User agent7\n    ProxyJump jump@gw.example.com\n"}

With that in ~/.ssh/config, the agent works on the booked nodes like on any server. On each node of a multi-node job, the open-source meshvpn net env prints the variables torchrun needs and picks the fastest path between the nodes:

on gpu2, gpu3, gpu5, gpu6
$ eval $(meshvpn net env --master gpu2 gpu2 gpu3 gpu5 gpu6)
$ torchrun --nproc_per_node=8 train.py

In a shared booking, several jobs share the same nodes. Then reserve GPUs, so jobs don't take each other's: meshvpn gpu reserve gpu2 -n 4 --for 3h prints CUDA_VISIBLE_DEVICES, and meshvpn gpu release frees them. See Train across GPU nodes for launch, gpu, share and fetch.

STEP 8

Cancel and clean up

When the job is done early, the agent gives the nodes back:

$ curl -s -X POST -H "$MV" https://portal.example.com/api/networks/lab/bookings/b7c1e2f0/cancel

Users and agents can cancel their own bookings; admins can cancel any. At the end of a booking, the nodes lock the account, remove sudo and stop all its processes, so a forgotten job doesn't block the next one.

STEP 9

Teach your agent

meshvpn guide on any node prints instructions for AI agents: the rules, the commands for each task, and what's in the network right now. Point your agent at it, for example in AGENTS.md or CLAUDE.md:

AGENTS.md
Book GPU nodes through https://portal.example.com/api/book (key in $MESHVPN_KEY),
cancel the booking when you're done, and run `meshvpn guide` on a node before
working with other machines.

For Claude Code, install the guide as a skill: mkdir -p ~/.claude/skills/meshvpn && meshvpn guide --skill > ~/.claude/skills/meshvpn/SKILL.md.
