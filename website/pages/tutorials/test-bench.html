Book a test bench

You set up a bench of devices. People book one or several of them, exclusive or shared, and log in from anywhere with nothing but their SSH key. During the booking they have their own account with sudo. When it ends, the account is locked again.

You need: 3+ Linux machines, one reachable from outside on port 22Works on: Linux devices and gateways, any admin machine

Steps

1. The plan 2. Install the nodes 3. Start the trial 4. Tag devices and gateway 5. Add people 6. Make devices bookable 7. Book 8. Log in from outside 9. When a booking ends 10. Keep an eye on it

STEP 1

The plan

A bench network has three kinds of machines. You can combine roles on one machine.

RoleIn this tutorialWhat it needs
Admin nodeadmmeshvpn; this is where you change the policy
Gatewaygw, reachable as gw.example.commeshvpn and sshd, port 22 open to your users
Devicesdev1, dev2, dev3meshvpn and sshd, Linux
Peoplealice, boban SSH client and a key pair, nothing else

The admin signs a policy: who the users are, which devices they may book, which nodes are gateways, and the bookings. Every node gets the policy and enforces its own part. The gateway lets each key through to its booked devices only. The devices create the accounts.

STEP 2

Install the nodes

The enterprise build comes from its own release repository. On the admin node, create the network:

on adm
$ curl -fsSL https://github.com/PlugOvr-ai/meshvpn-enterprise-releases/releases/latest/download/install.sh | sudo sh
$ sudo meshvpn init --network bench --endpoint gw.example.com:7870
$ sudo meshvpn install

init prints an invite. Each invite admits one node within 24 hours by default; print more with sudo meshvpn invite. On the gateway and on each device, install and join in one step:

on gw, dev1, dev2, dev3
$ curl -fsSL https://github.com/PlugOvr-ai/meshvpn-enterprise-releases/releases/latest/download/install.sh | sudo sh -s -- join mesh1-...

Check that everyone is there with meshvpn status.

Endpoint. --endpoint is where other nodes reach the first node. Use the address of a machine that others can connect to on port 7870. Nodes behind NAT still find each other; see firewalls and NAT.

STEP 3

Start the trial

The enterprise features need a license. A 30-day trial for this network is free and starts from the admin node:

on adm
$ meshvpn license terms
$ sudo meshvpn license trial --email you@example.com --company "ACME Labs" --accept-terms
$ meshvpn license show

Starting a trial means you accept the license terms. The audit log records who accepted which version, and when. Once you have a license file, install it the same way: sudo meshvpn license install <file> --accept-terms. Plans and prices are on the pricing page.

Older releases. Releases up to v0.16.1 don't know --accept-terms. There, leave the flag out, or run sudo meshvpn update first.

STEP 4

Tag devices and gateway

Tags let you write rules for groups of machines instead of single names. Each node tags itself:

# on dev1, dev2, dev3
$ sudo meshvpn tag add bench
# on gw
$ sudo meshvpn tag add gateway

Then tell the policy which nodes are gateways:

on adm
$ sudo meshvpn gateway add tag:gateway
$ meshvpn gateway list

Open port 22 of the gateway to wherever your users are. Users log in to the gateway as jump, an account that can only forward connections to booked devices.

STEP 5

Add people

A user is a name and one or more SSH public keys. Ask alice and bob for their public keys (~/.ssh/id_ed25519.pub), then:

on adm
$ sudo meshvpn user add alice --key-file alice.pub
$ sudo meshvpn user add bob --key "ssh-ed25519 AAAAC3Nza... bob@laptop"
$ sudo meshvpn group set testers alice bob
$ meshvpn user list

user add on an existing name replaces their keys. --key and --key-file can be repeated. Remove someone with sudo meshvpn user rm bob. group set sets the members; with no members it removes the group.

STEP 6

Make devices bookable

A device rule says which nodes can be booked, by whom, for how long, and whether the user gets sudo:

on adm
$ sudo meshvpn device add tag:bench --who group:testers --max 8h
# a device without sudo for the user
$ sudo meshvpn device add dev3 --who alice --max 2h --no-sudo
$ meshvpn device list

--who takes user names, group:<name> or *, separated by commas; without it every user may book. Without --max there's no limit. Users get sudo without a password unless the rule says --no-sudo. Remove a rule with sudo meshvpn device rm tag:bench.

STEP 7

Book

One booking can hold several devices. An exclusive booking (the default) can't overlap any other booking of the same device. Shared bookings may overlap other shared ones.

on adm
# two devices for alice, from now, for two hours, nobody else meanwhile
$ sudo meshvpn book dev1 dev2 --user alice --for 2h
booked dev1, dev2 for alice exclusively from 2026-11-03 09:00 UTC until 2026-11-03 11:00 UTC (id b3f09a1c)
# shared with other shared bookings
$ sudo meshvpn book dev3 --user bob --for 1d --shared
# any two free bench devices tomorrow morning
$ sudo meshvpn book tag:bench --count 2 --user bob --from 2026-11-04T09:00+01:00 --until 2026-11-04T13:00+01:00 --note "firmware 2.4 regression"

--from takes now (the default), a relative time like +1h, or a time with a zone. Give the length with --for or the end with --until. With --count, meshvpn picks free devices from one selector.

anywhere in the network
$ meshvpn bookings
$ meshvpn bookings --all          # also those that ended
$ sudo meshvpn cancel b3f09a1c     # on adm: ends a running booking now, or cancels an upcoming one
Booking without a terminal. In the portal, people book devices for themselves, see their bookings and cancel them.

STEP 8

Log in from outside

alice doesn't install anything. With her key, she jumps through the gateway to the booked device:

on alice's laptop
$ ssh -J jump@gw.example.com alice@dev1.mesh
alice@dev1:~$ sudo dmesg | tail

To save typing, she adds this to ~/.ssh/config once:

~/.ssh/config
Host *.mesh
    User alice
    ProxyJump jump@gw.example.com

From then on ssh dev1.mesh, scp, rsync and VS Code Remote SSH work as usual. Outside her bookings the gateway doesn't let her key through, and on the device her key only works from the gateway.

STEP 9

When a booking ends

Each device takes care of its own accounts. When alice's booking starts, dev1 creates or unlocks the account alice and adds her sudo rule. When it ends or is cancelled, the device:

  • locks the account,
  • removes the sudo rule,
  • stops all of alice's processes, including open SSH sessions.

Her home directory stays, so her files are there at the next booking. The gateway stops forwarding her key at the same moment.

STEP 10

Keep an eye on it

$ meshvpn device list     # bookable devices, online or not, booked by whom
$ meshvpn audit           # who changed what: users, rules, bookings, licenses
$ meshvpn audit -n 100

Changing the policy needs root on an admin node. Add more admins with sudo meshvpn admin add <node>. If the license expires, the last policy stays in force, so devices stay protected, but you can't change it until a new license is installed.
