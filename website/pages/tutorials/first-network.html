Your first network

Connect a server, a workstation and a laptop into one private network. Every machine gets a fixed address and a name like gpu1.mesh, wherever it is.

You need: two or more machines, root on eachWorks on: Linux, macOS, Windows 10/11

Steps

1. How it fits together2. Install3. Create the network 4. Add machines5. Names and tags6. SSH between nodes 7. Check and update

STEP 1

How it fits together

meshvpn has no coordination server. Each machine (a node) has its own key, picks its address in 100.64.0.0/10 from that key, and learns about the other nodes by gossip. Nodes connect directly where they can, over UDP through NAT, and relay through each other where they can't. All traffic is encrypted end to end.

You start the network on the machine that is easiest to reach, usually a server with a public address or a DNS name. It is not special to meshvpn. It is only a good first contact for the others, and the network keeps working without it.

STEP 2

Install meshvpn

On Linux and macOS, one command installs the static binary. It checks the download's SHA-256 checksum and uses the machine's proxy if one is set.

Linux, macOS
$ curl -fsSL https://github.com/PlugOvr-ai/meshvpn/releases/latest/download/install.sh | sudo sh

On Windows, open PowerShell as administrator. The installer adds the Wintun driver and a task that starts meshvpn at boot.

Windows
PS> irm https://github.com/PlugOvr-ai/meshvpn/releases/latest/download/install.ps1 | iex

Check it with meshvpn --version. Debian and Fedora users can also take the .deb or .rpm from the download page.

No root? Add --user to install into your home directory. See Containers, rootless and the browser desktop.

STEP 3

Create the network

On the server, create the network and run meshvpn as a service:

on the server
$ sudo meshvpn init --network lab --endpoint vps.example.com:7870
$ sudo meshvpn install
  • --endpoint is the address other nodes use to reach this one. Open TCP and UDP port 7870 in its firewall and in the cloud provider's security group.
  • install starts meshvpn at boot: systemd on Linux, launchd on macOS, the Task Scheduler on Windows.
  • init prints the first invite code (mesh1-…). This node is now the network's admin.
$ meshvpn status
● vps  100.78.210.211  (3f9c21a0 on mesh0, network "lab")
  reachable at: vps.example.com:7870

No other nodes known yet.

STEP 4

Add machines

On the admin node, create an invite for each new machine. An invite admits one machine within 24 hours unless you say otherwise.

on the server
$ sudo meshvpn invite
$ sudo meshvpn invite --uses 5 --expires 7d   # for several machines

On the new machine, install and join in one step. This also starts the service:

on the workstation
$ curl -fsSL https://github.com/PlugOvr-ai/meshvpn/releases/latest/download/install.sh | sudo sh -s -- join mesh1-…

If meshvpn is already installed, run sudo meshvpn join mesh1-… and then sudo meshvpn install. On Windows, pass the invite to the installer:

Windows
PS> & ([scriptblock]::Create((irm https://github.com/PlugOvr-ai/meshvpn/releases/latest/download/install.ps1))) join mesh1-…

Within seconds the nodes see each other:

$ meshvpn status
● workstation  100.122.144.177  (a69e03bd on mesh0, network "lab")

NAME      IP               STATUS      RTT  PATH
vps       100.78.210.211   online     15ms  direct UDP 178.77.77.96:7870
gpu1      100.64.166.69    online      1ms  direct UDP 192.168.1.160:7870
Used or expired invite? It is refused right away with a clear message. Ask an admin for a new one.

STEP 5

Names and tags

Every node is reachable as <name>.mesh from every program: ping gpu1.mesh, ssh gpu1.mesh, http://gpu1.mesh:8888. The machine's host name is its node name. Pick another one with --name when joining, or later:

$ sudo meshvpn rename gpu1

Tags group machines, so commands can address them together as tag:gpu:

$ sudo meshvpn join mesh1-… --tag gpu,trainer   # when joining
$ sudo meshvpn tag add gpu                      # or later, on the node itself
$ meshvpn nodes tag:gpu                         # CPUs, memory and GPUs of those nodes

STEP 6

SSH between nodes

Each machine decides for itself who may log in to it without a password. Nodes publish their users' public SSH keys, and the rules on the target say which of them may log in as which account. Run these on the machine you want to log in to:

on the server
$ sudo meshvpn ssh allow alice@laptop --as alice   # alice on the laptop, as alice
$ sudo meshvpn ssh allow laptop --as ubuntu        # any user of the laptop, as ubuntu
$ sudo meshvpn ssh allow everyone --as ubuntu      # every node, also later ones
$ sudo meshvpn ssh deny alice@laptop               # take it back
$ meshvpn ssh list                                 # rules, offered keys, refused logins

Prefer a screen? sudo meshvpn ssh opens an editor with every node and user in a grid. Then, on the laptop:

on the laptop
$ ssh alice@vps.mesh

Host keys are known in advance, so there is no "are you sure?" prompt. Each allowed key works only from its own node's mesh address, which can't be spoofed.

Refused? meshvpn ssh list on the target names the reason. Usually it is the wrong user name, or the source machine has no SSH key yet (create one with ssh-keygen; it is published within a minute).

STEP 7

Check and update

doctor checks the setup on a node and says how to fix each problem it finds: the daemon, firewalls, conflicts with other VPNs, UDP paths, SSH logins, admins and updates.

$ sudo meshvpn doctor

Updates are never installed by themselves. meshvpn status tells you when a new release is out. Install it on each node:

$ sudo meshvpn update

To keep the network independent of one machine, make a second node an admin:

$ sudo meshvpn admin add workstation
$ meshvpn admin status
CommandWhat it does
sudo meshvpn forget old-laptopRemoves an offline identity, for example of a reinstalled machine
sudo meshvpn ban stolen-laptopThrows a node out for good; the network gets a new key
sudo meshvpn uninstallStops the service and keeps the configuration
