Containers, rootless and the browser desktop

GPU containers, shared servers without sudo, images without an SSH server or a display. meshvpn adapts to each, and still gives you a shell and a graphical desktop on every node.

You need: a network from Your first networkWorks on: Linux (rootless and desktop sessions), any OS as the viewer

Steps

1. Containers with a network interface2. Userspace mode3. Without root 4. No SSH server needed5. The desktop in the browser6. A full Xfce desktop 7. The terminal console

STEP 1

Containers that may have a network interface

Start the container with --cap-add=NET_ADMIN --device /dev/net/tun. meshvpn then works exactly as on a normal machine, with its interface mesh0. Without systemd, meshvpn install starts meshvpn in the background and prints the line for the container's entrypoint:

entrypoint
/usr/local/bin/meshvpn --dir /etc/meshvpn up &

Keep /etc/meshvpn on a volume, so the node keeps its identity when the container is recreated.

STEP 2

Root, but no NET_ADMIN: userspace mode

Without /dev/net/tun or the NET_ADMIN capability, meshvpn switches to userspace mode by itself. It runs a small TCP/IP stack in its own process, and meshvpn status shows mode: userspace.

  • Into the container: other nodes reach its services directly: ssh box.mesh, curl http://box.mesh:8080. Ping works.
  • Out of the container: ssh user@node.mesh works without setup. Other programs use the SOCKS5 proxy on port 1055.
inside the container
$ ssh ubuntu@gpu1.mesh
$ ALL_PROXY=socks5h://127.0.0.1:1055 curl http://hub.mesh:8000
$ meshvpn nc gpu1 5432   # stdin/stdout to a port, for other tools

Limits: TCP and ping only, no UDP. Programs that ignore proxy settings can't reach out to the mesh. It is slower than kernel mode, about 30 to 40 MB/s. Force the mode with --userspace on init or join, or set userspace = "always" or "never" in the configuration.

STEP 3

Without root: the rootless install

No sudo on a shared server? Install meshvpn for your user only. This also happens by itself when sudo is missing.

as your user
$ curl -fsSL https://github.com/PlugOvr-ai/meshvpn/releases/latest/download/install.sh | sh -s -- --user join mesh1-…
  • The binary goes to ~/.local/bin, the configuration to ~/.config/meshvpn. Nothing is written outside your home directory except a marked Host *.mesh block in ~/.ssh/config.
  • It runs in userspace mode, so the rules of step 2 apply.
  • meshvpn install starts it as a systemd user service. To keep it running after you log out, an admin runs sudo loginctl enable-linger <user>. Without systemd it uses a @reboot crontab entry.
  • status, rename, tag, share, invite, ssh allow, update and uninstall work without sudo.
What it can't do: write /etc/hosts (only ssh and the proxy know the .mesh names), or log in anyone but its own user. Only one rootless install per machine can use the default ports.

STEP 4

Logins without an SSH server

Most Docker images have no sshd. meshvpn then answers ssh user@node.mesh itself, with the same rules as meshvpn ssh allow. It supports shells with a terminal, commands with exit codes, scp and sftp, and -L port forwarding. Sessions get the container's environment, so PATH, CUDA and conda from the image are there. meshvpn status shows ssh server: built-in.

For machines everybody works on, such as cluster nodes, open logins up when joining. Every node of the network, also ones that join later, may then log in as the named account:

$ curl -fsSL https://github.com/PlugOvr-ai/meshvpn/releases/latest/download/install.sh \
  | sudo sh -s -- join mesh1-… --ssh-allow-all ubuntu

meshvpn ssh allow also works before meshvpn runs for the first time, for example in a Dockerfile: it writes the rule to the configuration.

Choose: ssh_server = "auto" (the default) uses the built-in server only where no sshd serves port 22. "always" and "never" force it on or off. Agent forwarding, X11 forwarding and -R aren't supported.

STEP 5

The desktop in your browser

$ meshvpn desktop gpu1              # opens gpu1's desktop in your browser
$ meshvpn desktop gpu1 -u ubuntu    # as another account

This works on machines without any graphical system. meshvpn brings a small static X server (about 5 MB, downloaded on first use) and does the rest itself: window manager, screen transfer, keyboard in any layout, clipboard in both directions. Install only the applications you want to run.

  • Same logins as SSH. Whoever may ssh ubuntu@gpu1.mesh may open ubuntu's desktop, and nobody else.
  • The bar lists the windows. Apps starts installed applications or any command, Clipboard shows what was copied on the desktop, and ⛶ goes fullscreen.
  • Files browses the node's files: an image viewer, text previews, downloads, and uploads by dropping files on the panel.
  • Sessions keep running when you close the tab. ⏻ in the bar, or meshvpn desktop stop on the node, ends them.

Machines without internet: copy meshvpn-desktop-<arch>.tar.gz from the release and run meshvpn desktop setup --from <file>. That also works in a Dockerfile.

Logged in from outside the mesh? meshvpn desktop notices and prints the forward to run on your computer, for example ssh -L 7880:127.0.0.1:7880 you@vps.example.com. Then open the printed link locally.

STEP 6

A full desktop with Xfce

The built-in desktop shows one application at a time. For a panel with an applications menu, a file manager and windows you can move, install Xfce on the node once. It needs root and about 300 MB, and uses apt, dnf, apk or zypper.

on the node
$ sudo meshvpn desktop setup --xfce   # or add xfce4 to the Dockerfile

From then on meshvpn desktop gpu1 opens Xfce. A session started before Xfce was installed keeps the built-in desktop: end it with ⏻ and reconnect. --plain keeps the minimal desktop.

STEP 7

The terminal console

Sometimes all you have is an SSH login on one machine. Type meshvpn on it to get a full-screen terminal desktop:

$ meshvpn            # or: meshvpn console -u ubuntu
  • Tab 0 lists the nodes with status, path, latency, GPUs and tags, and details of the selected node.
  • Enter opens a shell on the selected node in a new tab. u logs in as another user, d prints a desktop link.
  • Switch tabs with Alt+0…9, or like tmux with Ctrl+B and then 0…9, n, p, w.

Each node announces its default login. Set it on the node with sudo meshvpn ssh default-user ubuntu; nodes joined with --ssh-allow-all ubuntu announce ubuntu by themselves.
